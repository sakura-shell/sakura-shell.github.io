# AI判定の精度を上げるための検証（2026年10月8日）

道具：`tools/experiments.html`・`tools/experiments.js`・`tools/run_experiments.py`（画面を出さない Chrome で動かす）。
結果の数値：`docs/experiments/*.json`

## 評価のしかた

学習に使っていない「別の個体」だけで評価する。

| 評価用 | 枚数 | 内容 |
| --- | --- | --- |
| 見本の箱 | 36 | 完成見本の箱（references/box_sample.jpeg）の各マス |
| チラシの箱 | 36 | チラシに載っている箱の写真（tools/fixtures/flyer_box.jpg）の各マス。画質が低い |
| 別の個体 | 2 | training/test/（さくら貝） |

1枚の差＝2.8%。同じ条件でも、学習のたびに3〜5%ほどぶれる。

## 今のAI（MobileNet v1 幅0.50・線形の分類器・水増し12枚）

見本の箱：1位で正解 33〜44%・5位以内 72〜78%／チラシの箱：1位 8〜19%・5位以内 44〜53%（合計72枚で1位 22〜29%）

## 試したこと

| 試したこと | 結果 |
| --- | --- |
| 背景を灰色で塗ってから判定（箱の水色と、学習写真の白い背景の違いをなくす） | 下がった（見本の箱 39% → 22〜36%） |
| さらに色かぶりを直す | 下がった（見本の箱 33%） |
| 貝の色の分布を特徴に足す | 下がった（見本の箱 39% → 22〜25%） |
| 途中の層の特徴も使う／強い所を重く平均（GeM） | 変わらない〜下がった |
| 途中の層だけ | 大きく下がった（ほぼ当てずっぽう） |
| 分類の方法（平均との近さ・いちばん近い1枚） | 変わらない（ぶれの範囲） |
| 水増しの枚数（0・4・12・30） | 0枚より4〜12枚がよい（合計72枚で19% → 26〜29%）。30枚に増やしても上がらない |
| 分類器の抑え（l2） | 1e-3 は下がる。1e-4・1e-5・0 はぶれの範囲で同じ |
| （以前）判定の工夫（4枚の平均）・背景を実写にした水増し | 変わらない |

→ 今のモデル（MobileNet v1 幅0.50）のまま、写真の扱い方や分類の方法を変えても、上がらない。

## 別の個体を学習に加えると（いちばん効果が大きい）

評価用の箱の一方（36個＝各種類1個）を学習に加え、もう一方で評価した（2回）。

| 評価 | 加える前 | 別の個体を1個ずつ加えたあと |
| --- | --- | --- |
| 見本の箱（チラシの箱を加えた） | 1位 36〜44%・3位以内 64%・5位以内 72〜75% | 1位 44〜50%・3位以内 67〜81%・5位以内 78〜86% |
| チラシの箱（見本の箱を加えた） | 1位 11〜14%・3位以内 22〜25%・5位以内 47〜50% | 1位 17〜19%・3位以内 44〜58%・5位以内 53〜75% |

今の学習用の写真は、ほとんどが各種類1個の貝（同じ個体）を撮ったもの。AIは「その1個」を覚えてしまい、別の個体を当てにくい。
**別の個体の写真を加えるのが、いちばん確実に効く**（1個加えるだけで、5位以内が10〜25ポイント上がった）。

## 新しい画像認識のモデル：DINOv2-small（2026年10月8日にご了承をいただき読み込み）

DINOv2-small（Meta、Apache-2.0。transformers.js＋ONNX Runtime でブラウザの中で動かす。8ビットに軽くした版 約24MB）で、写真の特徴を取り出して比べた。

| 条件 | 見本の箱（1位/3位以内/5位以内） | チラシの箱 | 合計72 |
| --- | --- | --- | --- |
| 今のモデル（MobileNet v1）・水増し4・線形 | 38.9 / 61.1 / 75.0 | 19.4 / 36.1 / 50.0 | 29.2 / 48.6 / 62.5 |
| DINOv2・水増し4・線形 | 58.3 / 77.8 / 83.3 | 16.7 / 44.4 / 58.3 | 37.5 / 61.1 / 70.8 |
| DINOv2・水増し4・平均との近さ | 63.9 / 86.1 / 88.9 | 22.2 / 38.9 / 58.3 | 43.1 / 62.5 / 73.6 |
| **DINOv2・水増し4・いちばん近い1枚** | **69.4 / 80.6 / 83.3** | **25.0 / 58.3 / 66.7** | **47.2 / 69.4 / 75.0** |
| DINOv2・水増しなし・線形 | 61.1 / 75.0 / 83.3 | 22.2 / 55.6 / 69.4 | 41.7 / 65.3 / 76.4 |
| DINOv2・水増しなし・いちばん近い1枚 | 66.7 / 83.3 / 86.1 | 22.2 / 47.2 / 58.3 | 44.4 / 65.3 / 72.2 |
| DINOv2・背景を灰色に塗る | 44〜50 / 64〜67 / 75〜78 | 11〜17 / 25 / 31〜33 | 30.6 / 44〜46 / 54 |

**DINOv2 ＋ 別の個体を1個ずつ加える**（両方を組み合わせると、さらに上がる）

| 評価 | 今のモデル（加える前） | 今のモデル＋1個 | DINOv2＋1個（いちばん近い1枚／線形） |
| --- | --- | --- | --- |
| 見本の箱 | 1位 36〜44%・5位以内 72〜75% | 1位 44〜50%・5位以内 78〜86% | **1位 75%・5位以内 92〜97%** |
| チラシの箱 | 1位 11〜14%・5位以内 47〜50% | 1位 17〜19%・5位以内 53〜75% | **1位 56〜61%・5位以内 86〜89%** |

**速さと大きさ**（Chrome・計算を1/4の速さに落とした状態で、写真1枚＝左右反転と2回の計算）

| | 判定1回 | 読み込むファイル |
| --- | --- | --- |
| 今のモデル（MobileNet v1・画像処理(WebGL)） | 約0.02秒 | 約7MB |
| DINOv2-small（8ビット・計算1本(wasm)） | 約2.6秒（反転なしなら約1.3秒） | 約47MB（モデル24MB＋動かす部品23MB） |

GitHub Pages では計算を並べる設定（複数の計算の同時実行）が使えないため、1本で計算した値。実機（iPhone・Android）での速さは未確認。

## わかったこと・おすすめ

1. **モデルを DINOv2 に替える**：別の個体の正解率が大きく上がる（見本の箱で1位 39% → 約65%、5位以内 75% → 約85%）。代わりに、判定に1〜3秒かかり、初回の読み込みが約47MBになる
2. **別の個体の写真を集める**：どちらのモデルでも効き、DINOv2 と組み合わせると、見本の箱で1位75%・5位以内90%以上
3. 背景を塗る・色の分布を足す・特徴の取り方を変える、などの細工は効かない（どちらのモデルでも）

## 次に試すこと

1. DINOv2 をサイトに組み込む場合：左右反転なしでの正解率、WebGPU（使える端末で速くなる）、36種類以外の判定の調整、実機での速さ
2. 別の個体の写真を集める（スタッフの「送付する」、動画からの切り出し）。目安：1種類につき別の貝3個以上
