# 三十六歌仙貝 デジタルガイド：レビュー結果

作成日：2026年9月29日

## 結論

チラシの水色・ピンク・黄色・濃紺、ロゴ、柔らかい角丸を引き継げており、デザインの方向性は維持できます。番号と実物の箱の位置関係、写真の外部送信をしない構成、保存前の確認、写真と手動操作への代替導線も良い土台です。

優先すべきは、**「撮れば分かる」という期待を修正すること、箱の操作を小さいマスへのタップに依存させないこと、未確認情報を本当に表示しないこと**です。自動判定・3D・ARを増やす前に、写真で見比べる／手で記録する体験を完成させてください。

- 以下の「画面」は画像で確認した事実、「コード」は静的に確認した事実、「要検証」は実行・実機試験が必要な項目です。ブラウザ起動、実機操作、画像認識の再測定は今回実施していません。READMEの試験結果は実装者の報告として扱います。
- ファイルパスはZIP内の `36shells_review/` からの相対パスです。更新版の章番号と改善IDを対応させています。

## 必須

### M01 撮影前から「写真で見比べる」と伝える

対象：01・02・06・07／`site/assets/js/views/home.js`、`views/identify.js`、`views/compare.js`、`lib/identify.js`。更新先：5.1・5.4。

画面とコード：ホームは「撮って調べる」、撮影前の画面は撮影を促し、自動判定不可の説明は撮影後に出ます。写真を撮る手間をかけてから制約を知る流れです。

修正：ホームは「拾った貝を、写真で見比べる」。撮影前に「撮った写真と図鑑を見比べます。自動判定はありません。」と短く説明。撮影後は「下の写真から、似ている貝を選んでね」。学習データ不足などの開発事情はREADMEへ移す。自分で選んだ一覧を「AIの候補」のように扱わない。

### M02 未確認情報の表示条件を統一する

対象：03〜07／`site/data/shells.json`、`data.js`、`ui.js`、`views/detail.js`、`views/compare.js`、`views/parts.js`、`CONTENT_TODO.md`。更新先：5.2・5.3・6。

コード：3・8・19番の特徴は `status: "sheet"` のため表示されますが、CONTENT_TODOでは文言の確認待ちです。35番の括弧内表記も確認待ちのまま `read`。20番の形は確認待ちでも絞り込みに使われます。名称・ふりがな・分類・レア度は確認状態の管理が一様ではありません。

修正：資料に記載されていることと、その転記を確認したことを分離。疑義のある任意項目は表示・検索・絞り込みから除外し、原本確認後のみ公開。26・35番の分類欠落を「その他の形」と断定しない。番号・名称・箱位置は全36枠の公開前照合対象とし、曖昧な値を補完しない。

### M03 小さいマスを押さなくても記録できるようにする

対象：09〜12・14／`views/boxgrid.js`、`views/box.js`、`views/scan.js`、`site/assets/css/style.css`。更新先：5.5・5.6・7。

画面：全体表示のマスは幅375pxで約35px、320pxで約28pxという依頼書記載と整合し、番号・状態・写真が密集しています。拡大機能はすでにあります。

修正：4行×9列の全体図を維持し、修正時には拡大表示または番号順の大きい操作リストを提供。「次の要確認」「次の変更マス」で移動できるようにする。操作領域は原則44×44 CSS px以上、主操作48px以上を本企画の設計目標とする。小さい全体図だけを編集の入口にしない。

### M04 範囲・向きの調整を片手で完了できるようにする

対象：08／`views/scan.js` の `drawAdjust`・`runRead`、`lib/boxreader.js`、`style.css` の `.adjust`。更新先：5.6・7。

画面とコード：画像は幅に合わせた高さで、回転ボタンは写真の下。四隅の補正はドラッグ中心です。`runRead` はそのまま射影補正へ進み、UI側では四隅の交差・重なり等を検証していません。

修正：写真全体・四隅・向き確認・次へを見渡せる表示にし、角の周囲に余白を確保。「角を選ぶ→上下左右で動かす」の代替を追加。交差・面積不足等の不正な枠は読み取らず修正案内。1番の目印が未確認なら、空箱の向きを自動確定したように扱わない。向きが分からなければ手動記録へ進める。

### M05 箱の自動読み取りに公開条件を設ける

対象：08・09・15／`views/scan.js`、`lib/boxreader.js`、`tools/box-test.html`、`README.md`、`CONTENT_TODO.md`。更新先：5.6・8・9。

資料：READMEは完成見本で貝あり31・要確認5、チラシで誤り1、合成画像で36正解と報告。実物の空箱・部分収集・屋外は未検証です。「誤り0」はこの限定例での結果であり、31/36を一般的な正解率にできません。

修正：一般公開は手動記録を確実な入口にし、自動読み取りは検証を通るまで開発用に限定。空・部分・満杯、白い／小さい貝、晴れ・曇り・影・反射、真上・斜め・向き違いを実物で検証。貝あり→空き、空き→貝あり、要確認率、位置ずれ、修正時間を分けて記録。数値の合格基準は検証前に運営側と決め、合成画像を実物試験の代わりにしない。

### M06 「空き」と「まだ分からない」を分ける

対象：03・06・09〜12／`views/parts.js:56` の `applyFilters`、`views/box.js`、`views/scan.js`、`store.js`。更新先：5.2・5.5・5.6。

コード：「箱にまだない貝」は `filled` 以外をすべて表示するため、空き・要確認・未記録が混在します。手動修正には未記録へ戻す選択肢がありません。

修正：「空いているマスの貝」は `empty` のみを対象にする。要確認・未記録は別表示し件数を添える。4状態を一貫して扱い、手動で「未記録に戻す」を可能にする。要確認が残った保存は許可し、「貝あり32・要確認4で保存」など結果を明示。誤判定は要確認以外にも起こり得るため、全体も確認できる導線を残す。

### M07 保存できない場合も、その場の記録を使えるようにする

対象：09・10・12／`store.js`、`views/scan.js`、`views/box.js`、`views/home.js`。更新先：5.7・6・9。

コード：保存失敗時の旧記録保護と画像を省く再保存はあります。一方、保存不能時の結果は各画面内にとどまり、通常の箱・一覧へ移って使い続ける共有の一時記録はありません。削除処理は例外を無視するため、失敗しても「記録を消しました」と表示し得ます。

修正：永続記録とタブ内だけの一時記録を分け、「この画面を開いている間だけ使う」を提供。保存済みという表示や日時を付けない。削除成功を確かめてから完了表示。保存・削除・再読み込み・キャンセルの失敗経路を確認する。

### M08 オフライン更新と他サイトのキャッシュを守る

対象：画面外の共通処理／`site/sw.js:42`・`:57`、`README.md`。更新先：5.7・7・9。

コード：起動時に現在の `m36-v1` 以外のキャッシュを全削除します。同じオリジンの別サイトにキャッシュがあれば影響する可能性があります。また通信優先でタイムアウトがなく、弱い通信ではキャッシュへの切り替えが遅れる懸念があります。後者の体感時間は未測定です。

修正：アプリと公開パスを識別する名前空間を付け、削除・検索を自分のキャッシュに限定。アプリ・データ・画像の版を管理し、差し替え画像も保存対象にする。利用中の編集を壊さず更新し、弱電波時も保存済み画面を先に使えるようにする。キャッシュを名前で分離する実装は [MDNのCacheStorage例](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage#examples) も参照。

### M09 公開手順を実際に存在する構成へ直す

対象：`README.md` 6、公開用構成（ZIPに未同梱）。更新先：3・8・10。

ファイル確認：READMEに記載された `.github/workflows/pages.yml` はZIPにありません。案内どおりにpushすれば公開される、と現時点ではいえません。

修正：利用する公開方法に合わせて設定ファイルを実装・同梱するか、設定ファイル不要の手順へ修正。公開リポジトリに一式を入れる手順も見直し、公開許諾のない参照資料・検証写真が含まれない構成を初めから作る。後から `.gitignore` に書くだけで既存の追跡や履歴が消える扱いにしない。

### M10 自治体側の公開確認と実機確認を完了条件にする

対象：全画面／`README.md`、`CONTENT_TODO.md`、`ASSETS.md`、`views/about.js`。更新先：3・6・7・9・10。

資料：素材利用条件、実機カメラ、屋外読み取り、実機オフラインが未確認です。公開先の想定アカウントや町の既存サイトの管理権限も、このZIPからは確認できません。

修正：権利者・公開許諾範囲・運営責任者・更新担当・問い合わせ先・本番URL・料金等の現行情報を確認。iPhone SafariとAndroid Chromeで一連の操作を確認し、実寸印刷したQRを読む。無料枠・超過時挙動・自治体企画での利用可否は採用時に公式情報で再確認する。GitHub Pagesは用途制限があるため、「観光だから問題ない」と断定しない（[GitHub公式の制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)）。

## 今回は再修正指示にしない事項

- 08の警告：`views/scan.js` は、検出できた場合の「ずれているかもしれません」と未検出を分岐済み。
- 13の不要な撮影枠・シャッター：`lib/camera.js` の `showMessage()` に非表示処理あり。表示の再確認は必要ですが、未修正と断定しません。
- 12の巨大なチェック：`style.css` 末尾に `.state-picker button svg` の20px指定あり。最新スクリーンショットで確認します。
- 15の内部スコア：開発検証画面の値です。ユーザー向け画面に確率が出ている証拠にはなりません。
- タップ領域44pxは本企画の屋外利用向け目標です。WCAG 2.2 AAのターゲットサイズは24 CSS pxを基本とし例外もあるため、「44px未満だからAA違反」とは判定していません（[W3C解説](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)）。
