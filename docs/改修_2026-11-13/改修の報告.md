## 2. ホームを1画面に収める仕組み

- 高さ：`height: 100dvh`（古いブラウザだけ、見えている高さを数で渡す）。下のタブと safe-area は高さの予算に含める。
- ロゴは「残った高さ」に合わせて全体を縮める（切らない）。
- 下の段は、画面に出た時点と、大きさ・文字の読み込み・表示設定が変わるたびに実測して、収まるまで段階を上げる：
  1. 最近の貝を、小さな写真つきの1行に
  2. 「ホーム画面に追加」の行をしまう（入口は「このサイトについて」に残る）・カードの高さを詰める
  3. 最近の貝をしまう（収集箱から見られる）・説明の文をしまう
- ロゴが本来の高さの6割より小さくなるときも、段階を上げてロゴに場所をゆずる。
- 横向きの低い画面は、ロゴを左・操作を右に並べる。
- `overflow: hidden` は、上の実測で収まったあとの仕上げ（隠れた操作は残らない）。

## 3. 小さく表示される件の切り分け

- 依頼者の端末の画面は、横幅が約804pxで描かれていた（402pt幅の iPhone の2倍）。同じ幅を手元で再現すると同じ崩れになった。**端末・ブラウザ側の設定（Safari の「ページの拡大/縮小」を小さくしている、または「デスクトップ用Webサイトを表示」）で起きる状態**で、サイトの viewport の指定（width=device-width, initial-scale=1）は正しい。
- サイト側の原因はなかったか：固定幅・min-width・横方向のはみ出しは、全画面で検査して見つからなかった（「見比べる」の横に送る写真の列は意図した動き）。ブレークポイントは 700px・960px。
- 警告の見分け（`looksZoomedOut()`）は、タッチ対応・画面の短い辺が500以下・描画の幅が端末の幅の1.3倍超、の推定。タブレット・パソコン・キーボード表示・画面回転では出ない作り。依頼者の端末では誤判定ではなく、実際に縮小されていた。
- 対応：起動時の警告をやめ、通常の幅で読みやすいことを基本に。幅の広い描画でも大きな空きが出ないよう直し（r29）、アプリ内の「大きめ」を用意した。
- **見送ったもの**：「スマホ向けレイアウト」を利用者が選ぶ切り替え。ページ全体の倍率（CSS の zoom）を使う必要があり、他の画面の作り（画面幅で切り替える指定）と合わず、全画面の検証が要る。指示書の「ページ全体への安易な拡大で対処しない」にも近いため、今回は入れていない。端末側の設定を戻す案内（「このサイトについて」の表示の欄）で対応。

## 6. 本番への反映手順と戻し方

反映（依頼者の「公開して」のあと）：
1. 合言葉・スタッフ用の鍵がファイルに入っていないか確かめる（`git grep`）
2. `git fetch` → `git rebase origin/main`（同じ場所に別の作業も公開しているため）→ `git push origin HEAD:main`
3. GitHub Actions の「サイトを公開」が成功したことと、公開サイトの版（sw.js の VERSION）が r30 になったことを確かめる
4. 利用者の端末では、次に開いたとき「更新データがあります」と出て、「更新する」で切り替わる

戻し方：
1. `git revert <今回のコミット>`（r30 のコミット）
2. `site/sw.js` の VERSION と `site/data/config.json` の appVersion を新しい番号（r31）に上げる（上げないと端末に届かない）
3. push。利用者には「更新データがあります」が出て、前の画面に戻る
- 収集記録・バッジの形式は変えていないので、戻しても記録は消えない。表示設定（`m36shells:display`）は残るが、前の版では使われないだけ。
