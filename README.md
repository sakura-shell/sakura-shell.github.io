# 三十六歌仙貝 デジタルガイド（MASUHOGAURA 36 shells Collection）

増穂浦海岸で36種類の貝を集める企画のための、スマートフォン向けWebサイトです。実物の水色のコレクションBOXと一緒に使います。

- 版：**2026.10.05-r8**（UI・操作性の改善〔比較画面・収集箱の記録・絞り込み・ホーム・初めての方へ〕。`site/data/config.json` の `appVersion`）
- 指示書：`SPEC.md`（レビュー反映・更新版）。初版とレビュー資料は `docs/review/`
- 最新の画面：`docs/screenshots/01`〜`19`（16〜19 が r6。前の版の画面は `docs/screenshots/r2/`、3Dの試作は `3d見送り/`）
- 素材（写真）の撮り方と渡し方：`docs/素材の渡し方.md`
- UI精査の記録：`docs/UI精査.md`
- 全ページの確認用PDF：`docs/全ページ確認_2026-10-05.pdf`（スマホ幅で全48画面。作り直すときは `python3 tools/serve.py` を起動したまま `python3 tools/capture_pages.py`）
- 状態：**改修コード完成**（確認用プレビュー）。実機確認・一般公開準備・公開は**未了**（第4章・第7章）

ログイン・会員登録・外部サーバーはありません。写真の処理も記録の保存も、利用者の端末の中で行います。有料API・有料データベース・有料認証は使っていません。ビルド作業も不要です（HTML・CSS・JavaScript のみ）。

## 1. 起動方法

### スマホで確かめる（同じWi-Fi・無料）

```bash
python3 tools/serve_lan.py
```

表示された `http://192.168.x.x:8737/` を、同じWi-Fiにつないだスマホのブラウザで開きます。サイトのファイルだけを見せる読み取り専用のサーバーで、インターネットには公開されません。http のため、オフライン用の保存は使えず、「カメラで撮る」はスマホの撮影画面を開く方法になります。Macがスリープすると開けなくなります。


必要なもの：Python 3（Mac には標準で入っています）

```bash
python3 tools/serve.py
```

- サイト：http://localhost:8736/site/
- 箱の自動読み取り（開発用）：http://localhost:8736/site/#/scan?dev=1（`?dev=1` を付けたタブでだけ有効。`?dev=0` で解除）
- 箱の読み取りの検証ページ：http://localhost:8736/tools/box-test.html
- AI判定の学習と評価：http://localhost:8736/tools/train.html
- 3D表示の検証：http://localhost:8736/tools/model-test.html
- 表示崩れの自動チェック：サイトを開いてコンソールで `const { runAll } = await import('/tools/ui-audit.js'); await runAll();`
- 一般公開前のチェック：`python3 tools/check_release.py`

カメラは HTTPS か localhost でしか使えません。スマホ実機では HTTPS の公開先で開いてください（第6章）。

### 2つの表示モード（`site/data/config.json` の `mode`）

| モード | 使う場面 | 表示される情報 |
| --- | --- | --- |
| `preview`（現在） | 町・関係者の確認、実機試験 | 原本と照合済み（`confirmed`）の情報に加え、資料から転記しただけ（`transcribed`）の情報を「照合待ち」付きで表示。利用許諾を確認中の写真・ロゴも表示し、画面上部に「確認用プレビュー」と出す |
| `public` | 一般公開 | `confirmed` の情報と、利用許諾が確認済みの写真・ロゴだけ。それ以外は出さない（写真は「写真準備中」、ロゴは文字表示） |

疑義のある情報（`unclear`）は、どちらのモードでも画面・検索・絞り込みに出しません。

## 3. 機能の状態

### 使える機能（一般向け）

| 画面 | できること |
| --- | --- |
| ホーム | ロゴ（チラシの表紙）とチラシの波の帯、3つの入口（貝を探す／この貝、なあに？／箱を記録する）。記録があれば進み具合のリングと「箱の記録 4/36」「要確認 1」を表示し、ロゴを小さく。背景にチラシの線画に合わせた淡い貝の模様 |
| 貝を探す | 番号・名前で検索。形（表示してよい分類がある場合）、「空いているマスの貝」「要確認」「未記録」（件数つき）で絞り込み。絞り込みは折り返して全部見える。0件のときは「条件を解除してすべて見る」。詳細から戻ると条件とスクロール位置を復元 |
| 貝の詳細 | 写真（拡大可。複数あるときは下の小さな写真の列で切り替え。一覧表から切り出した仮の写真は小さめに「参考写真」と表示）→ 名前 → 見分けるポイント（表示してよいものだけ）→ 見比べ → 箱の位置と記録 → 前の貝／次の貝 |
| この貝、なあに？ | 撮影または写真選択（表・裏・横の最大3枚）。AI判定を使わない設定のときは、撮影の前に「撮った写真と図鑑を見比べます。自動判定はありません。」と表示し、撮影後は一覧から見比べる |
| 見比べる | 自分の写真（表・裏の切り替え）と図鑑の写真を並べる。比較相手を変えても写真と絞り込みを保持 |
| この貝かな？（見比べチェック） | 撮った写真と図鑑の写真を並べ、「全体の形・色・模様・ふち」を1つずつ「似ている／ちがう／わからない」で選ぶ。「4つのうち3つが似ている」と本人の選択結果を表示（％ではない）。すべて似ていれば「〇番かもしれません」と「〇番を記録」（修正画面へ。保存は本人が押す）、ちがう項目があれば「ほかの貝と見比べる」。答えている間も2枚の写真を上に小さく固定表示 |
| デジタルの箱 | 実物と同じ4行×9列（右上が1番）。4つの状態（貝あり／空き／要確認／未記録）を共通で使用。タップは「選ぶ」だけで状態は変わらない。拡大時は表示範囲を小さな帯で表示 |
| 手で記録する | 大きい状態ボタン（貝あり／空き／要確認／未記録に戻す）、「前の番号／次の番号」「次の要確認へ」、番号順リスト。**小さいマスを押さなくても36マスすべてを記録できる**。保存ボタンは「貝あり4・要確認1で保存」のように結果を表示 |
| 保存と再開 | 保存日時つきで端末に保存。保存を押すまで記録は変わらない。容量不足なら写真を省いて状態だけ保存。保存できないときは「この画面を開いている間だけ使う」（一時記録。日時は付けず「閉じると消えます」と表示。前の記録は変えない）。削除は実際に消えたことを確かめてから完了表示。試作版（`m36:box:v1`）の記録は内容を確かめて新しいキーへ移行（旧データは残す）。壊れた記録は消さずに退避してから上書き |
| オフライン | 一度開くと基本の画面・データ・写真を保存。「このサイトについて」で準備状況を表示 |

**r6：撮影写真の取り込みとAI判定**（2026年10月5日）

- 提供の撮影写真125枚を、ファイル名の**貝の名前**で36種類に対応させて取り込み（写真のフォルダの番号はサイトの番号と振り方が違うため、番号は使わない。対応表は `tools/photo_names.json`）。白い背景の照明のむらを補正して貝を自動で切り出し、図鑑の写真（長辺1200px＋一覧用480px）と学習用（`training/photos/`）を作成。名前のない `DSC_2477`・`DSC_2479` はファイル名で24番に指定
- 貝の詳細・見比べの写真の切り替えを、小さな写真の列に変更（小貝は9枚＋参考写真）
- AI判定を学習し直し（撮影写真125枚＋一覧表の切り出し36枚、1枚あたり12通りの水増し）。成績（`docs/ai-evaluation.json`）：
  - 学習に使っていない写真31枚（**同じ個体を別の角度で撮ったもの**なので甘めの数字）：1位で正解 77%、5位以内 94%。「可能性が高そう」と出た21枚はすべて正解
  - 完成見本の箱の写真の36マス（**別の個体**・箱の中・低解像度）：1位で正解 44%、3位以内 61%、5位以内 72%（前回は1位 33%）
  - 提供のさくら貝（緑の紙の上・別の個体）の写真2枚：どちらも1位がさくら貝。定規が大きく写った写真は定規を貝と取り違えて誤判定
  - 「36種類以外かもしれません」の判定は**使わない**設定にした（同じ個体の写真だけで基準を決めると、見本の箱の5マスを誤って「36種類以外」とした）。36種類以外の貝の写真（`training/photos/other/`）を集めてから決める
- 写真のフォルダとチラシ（36種類一覧）の見比べ：名前の書き方の違いのほかは同じ貝。「千代の花貝」→4 花貝、「24.ものあら貝」→29、名前のない `DSC_2477`・`2479`→24 かたし貝、20 雀貝はチラシと色が違うがこの写真でよい（運営が確認）

## 5. 素材・情報の追加と確認

すべて `site/data/shells.json` と `site/data/config.json` を書き換えます（UTF-8）。変更後は `site/sw.js` の `VERSION` を上げてください（端末に保存された古い版を取り直すため）。

### 確認状態の付け方

各項目は次の形です。原本・実物で確かめたら `status` を `confirmed` にし、確認した人と日付を書きます。

```json
"name": { "text": "すだれ貝", "status": "confirmed", "source": "36種類一覧（原本）", "reviewedBy": "商工観光課 ○○", "reviewedAt": "2026-10-05" }
```

| status | 意味 | 表示 |
| --- | --- | --- |
| `confirmed` | 原本・実物で確認済み | どちらのモードでも表示 |
| `transcribed` | 資料から転記しただけ | プレビューでだけ「照合待ち」付きで表示 |
| `unclear` | 不鮮明などの疑義あり | 表示しない |
| `unconfirmed` | 未確認・未登録 | 表示しない |

対象：`name`（名前）、`ruby`（ふりがな）、`sheetName`（一覧表の［ ］内）、`shape`（形。アイコンがない枠は `value: null`）、`rarity`（星。意味の確認も必要）、`box`（箱の位置）、`features`（見分けるポイント）、`similar`（似ている貝）、`colors`（色）。

### 写真

写真は「番号との対応（`mapping`）」「利用許諾（`rights`）」「画質（`quality`）」を別々に管理します。一般公開では `mapping` と `rights` がどちらも `confirmed` の写真だけを表示します。

```json
"photos": [
  { "view": "front", "src": "assets/img/shells/12-front.jpg", "source": "2026年10月 志賀町撮影",
    "mapping": { "status": "confirmed", "reviewedBy": "…", "reviewedAt": "…" },
    "rights":  { "status": "confirmed", "source": "志賀町（職員撮影）", "reviewedBy": "…", "reviewedAt": "…" },
    "quality": "ok" }
]
```

`view` は `front`（表）・`back`（裏）・`side`（横）。`quality: "low"` の写真は小さめに表示します。写真を追加したら `ASSETS.md` の素材台帳にも記録してください。生成AIで作った貝の写真は使わないでください。

**提供された写真は、手で書き換えずに `python3 tools/import_photos.py` で取り込めます**（ファイル名から番号と表・裏・横を読み取り、表示用1600pxと一覧用480pxを作って登録。撮り方と名前の付け方は `docs/素材の渡し方.md`）。

### 3Dモデル・実物大AR

```json
"model": { "src": "models/12.glb", "iosSrc": "models/12.usdz", "unit": "m", "source": "標本を3Dスキャン", "license": "志賀町", "status": "confirmed" },
"specimenSize": { "lengthMm": 42, "source": "標本を実測", "status": "confirmed" }
```

`model.status` が `confirmed` なら「3Dで見る」（確認用プレビューでは `transcribed` も「照合待ち」付きで表示）、`specimenSize.status` も `confirmed` なら「ARで実物大を見る」が出ます。3D表示の部品（model-viewer、`site/vendor/` に同梱）は、ボタンを押したときだけ読み込みます。

**写真から3Dモデルを作って登録するには**（Mac 専用）：

```bash
python3 tools/make_model.py 12 materials/3d/12 --length-mm 38
```

写真から3Dモデルを作り（`tools/bin/make3d`。なければ自動でビルド）、Web用の `site/models/12.glb` に変換して、実測の長さに大きさを合わせて登録します。撮り方は `docs/素材の渡し方.md` の③。

### 運営・問い合わせ先・ロゴ

`config.json` の `operator`・`contact`・`brandAssets` を、確認できたら `status: "confirmed"` にします。一般公開モードでは、確認済みのものだけ「このサイトについて」やホームに出ます。

### 箱の自動読み取り・貝の判定

- 箱の読み取り：`config.json` の `features.boxScan`（`"dev"`＝開発用のみ、`"public"`＝一般向け）。しきい値は `lib/boxreader.js` の `THRESHOLDS`。変えたら `tools/box-test.html` で確認
- AI判定：`config.json` の `features.identify`（`"off"`・`"dev"`＝開発用のみ・`"public"`＝一般向け）。学習し直す手順は `docs/素材の渡し方.md` の②（`tools/make_training_manifest.py` → `tools/train.html` →「サイトに保存する」で `site/models/classifier.json` を更新）。判定の決め方（「可能性が高そう」にする確率など）は `classifier.json` の `decision`

### 参照画像から切り出し直す

```bash
python3 tools/extract_assets.py
```

（Pillow が必要：`pip3 install pillow`）

### 確認用の公開（GitHub Pages・無料）

2026年10月から、確認用プレビューを GitHub Pages で公開して、スマホで確かめられるようにしています。

- アカウント：`sakura-shell`、リポジトリ：`sakura-shell.github.io` → **https://sakura-shell.github.io/**
- `main` に push すると、`.github/workflows/pages.yml` が自動で公開する（1〜3分）。`config.json` の `mode` が `preview` の間は、検索エンジンに載らないよう noindex と robots.txt を付ける。**URL を知っている人は見られる**ので、URLの共有先に注意
- リポジトリは公開（無料で Pages を使う条件）。`references/`・`training/`・`materials/`・確認用の画像とPDFは `.gitignore` で入れていない
- このMacから push するときは、リポジトリだけに書き込める鍵（デプロイキー `~/.ssh/sakura_shell_deploy`）を使う
- **合言葉の画面**：確認用プレビューの間は、最初に合言葉を聞く（一度入れた端末では次から聞かない。全角・半角、大文字・小文字は区別しない）。変更は `python3 tools/set_passphrase.py "新しい合言葉"`、外すときは `--off`。config.json には合言葉そのものではなく、元に戻せない値だけを書く。**ファイル自体は公開の場所にあるので、本当の意味での非公開ではない**（うっかり見られるのを防ぐ程度）。一般公開（mode が public）では出ない

### 公開前に必ずやること

1. `python3 tools/check_release.py` で、名前・箱の位置の照合、運営・問い合わせ先の確認が終わっていることを確かめる
2. `config.json` の `mode` を `"public"` にする
3. `site/` の中に、利用許諾が確認できていない素材が残っていないか確かめる（一般公開モードでは表示しないが、ファイルとしては公開先に置かれる。許諾が得られない素材は `site/` から削除する）
4. 料金・受付・景品・海岸での注意などは、運営が確認した現行の情報だけを載せる

### GitHub Pages で公開する場合（設定ファイル `.github/workflows/pages.yml` 同梱）

1. **リポジトリを作る前に** `.gitignore` を確認する（`references/`・`tools/fixtures/` は除外済み）。公開リポジトリの中身は誰でも見られます。一度コミットした画像は履歴に残り、あとから `.gitignore` に書いても消えません
2. リポジトリの Settings → Pages → Source を「GitHub Actions」にする
3. `main` に push すると、`check_release.py --strict` に通った場合だけ `site/` を公開する（条件を満たさないと公開されない）
4. 実機確認のためにプレビュー版を出す場合は、Actions の「サイトを公開」を手動実行し「確認用プレビューを公開する」を選ぶ（検索エンジンに載らない設定を付けるが、URL を知っている人は見られる）

### QRコード

- 公開後の**安定した最終URLを直接**QRにする。期限のある短縮URLや、未承認のURLは使わない
- 実寸で印刷し、iPhone と Android の両方で読み取って、正しいページが開くことを確かめる
